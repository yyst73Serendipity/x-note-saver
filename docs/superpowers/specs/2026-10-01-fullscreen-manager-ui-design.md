# 收藏管理页全屏化设计

## 目标

把收藏管理页从居中的有限宽度卡片布局改成占满浏览器窗口的桌面应用布局，减少顶部区域和页面外边距对可用空间的占用。顶部采用已确认的紧凑深色导航；帖子收藏主区域继续使用项目当前实现，只通过更宽、更高的可用空间自然放大。

## 核心边界

本次改版只做两件事：

1. 管理页铺满浏览器窗口。
2. 将标题、账号同步状态和工具按钮整理为两行紧凑顶部导航。

左侧分类栏、搜索与排序、分类标题、帖子快速导航、帖子卡片和缓存说明沿用当前项目的结构、视觉和交互。不得借全屏化重新设计帖子卡片，也不得更改元素顺序。

## 页面结构

### 第一行：主导航

- 高度约 60 px，使用深墨色背景。
- 左侧依次展示 X 标识、“我的帖子札记”和收藏数量。
- 右侧依次展示同步状态点、账号头像、Google 邮箱、同步状态、“立即同步”和“退出登录”。
- “立即同步”使用 X 蓝实心按钮；“退出登录”使用深色背景上的描边按钮。

### 第二行：工具导航

- 高度约 42 px，使用白色背景并与主内容之间保留细分隔线。
- 按钮在右侧对齐，顺序保持为：导入、导出备份、清空全部数据、迁移本机数据、清除本机缓存、配置帮助。
- “配置帮助”使用正式按钮样式，点击后继续在新标签页打开现有 `setup.html`。
- “清空全部数据”保留危险操作颜色和现有确认流程。

### 主工作区

- 占据顶部导航以下的全部剩余宽度和高度。
- 页面取消 `max-width` 和外层 28 px 留白。
- 分类栏和内容区仍使用当前白色卡片、浅灰页面底色、边框、圆角和间距。
- 左侧分类栏宽度保持当前 210 px，不改变分类内容和操作方式。
- 右侧内容区使用剩余宽度，保留当前 14 px 内边距。

## 必须保持现状的区域

### 左侧分类栏

保持以下现有设计和行为：

- “全部”“稍后阅读”“未分类”和自定义分类入口。
- 数量统计。
- 新建分类。
- 拖拽排序。
- 重命名和删除。
- 当前分类选中状态。

### 搜索、排序和分类标题

- 搜索框与排序按钮继续位于同一行。
- 当前分类标题与帖子数量继续位于搜索栏下方。
- 保留当前字体、边框、圆角、间距和控件行为。

### 帖子快速导航

- 保留当前 22 px 宽刻度导航和渐变背景。
- 保留 `tweet-list` 的 30 px 左内边距关系，不额外增加轨道槽位。
- 每条刻度继续对应一条帖子，当前可见项、悬停、点击定位和滚动逻辑不变。
- 全屏后轨道随帖子列表高度自然延伸，不单独居中或改成悬浮胶囊。

### 帖子卡片

帖子卡片内部顺序必须保持当前实现：

1. 头像、作者、账号和帖子发布时间。
2. 收藏时间、分类下拉和右侧图标操作组。
3. 笔记引用条与标签；无笔记和标签时不显示。
4. 帖子正文。
5. 图片或视频区域。

继续使用当前卡片边框、连续列表、字号、行高、标签、图标按钮和悬停状态。全屏带来的“放大”只体现为列表可获得更大的显示宽度和高度，不使用 CSS 缩放，也不放大字体、图标或卡片内边距。

### 本地缓存说明

- 继续显示真实缓存大小和扩展存储权限状态。
- 位置仍在内容区底部，不参与主要操作层级。

## 响应式处理

- 桌面宽屏使用全屏双栏布局。
- 窗口变窄时，第二行工具导航保持单行并允许横向滚动，不能挤压账号状态到不可读。
- 在现有窄屏断点基础上调整分类栏宽度和内容区域，不改变帖子卡片内部顺序。
- 页面本身不产生横向滚动；帖子列表只负责纵向滚动。

## 交互与数据行为

本次不修改任何数据逻辑。以下行为必须保持不变：

- Firebase 登录和退出。
- 自动同步、立即同步、离线队列和冲突处理。
- 导入、导出、迁移、清空和清除本机缓存。
- 分类管理、搜索、排序、编辑笔记、查看原帖、复制正文、稍后阅读和删除帖子。
- 帖子快速导航定位逻辑。

## 涉及文件

- `manager/manager.html`：重组顶部标题、账号状态和工具按钮的容器结构。
- `manager/manager.css`：移除页面最大宽度与外层留白，实现全屏工作区和紧凑顶部导航。
- `manager/cloud-panel.css`：将账号同步控件适配到第一行主导航。
- `manager/cloud-panel.js`：仅在顶部元素位置变化需要时调整状态渲染，不修改同步逻辑。
- `tests/`：更新受 DOM 结构影响的测试，并验证现有帖子与分类交互保持不变。
- `README.md`：更新管理页布局和顶部操作说明。

## 明确不做

- 不重新设计帖子卡片。
- 不改变帖子卡片内部顺序。
- 不改成双列或瀑布流。
- 不增加右侧笔记面板。
- 不改变导航刻度样式、宽度或定位逻辑。
- 不调整 Firebase、Firestore、扩展权限和数据模型。

## 验收标准

1. 管理页占满浏览器可用宽度和高度，不再受 1180 px 最大宽度限制。
2. 顶部为确认的两行紧凑导航，配置帮助显示为按钮。
3. 主工作区填满顶部以下空间，分类栏和内容区没有多余的大面积外边距。
4. 分类的新建、拖拽、重命名、删除和切换行为正常。
5. 搜索、排序、帖子数量和空状态行为正常。
6. 导航刻度与帖子列表继续保持当前 22 px / 30 px 空间关系，定位行为正常。
7. 帖子卡片的结构、顺序、样式和所有操作与改版前一致。
8. 导入、导出、迁移、清空、缓存、登录和同步行为不变。
9. 常见桌面宽度和窄窗口下无页面级横向溢出。
10. `npm test` 与 `npm run build` 通过，并在 Chrome 中完成一次全屏管理页视觉检查。
